# 実行層


計画で決めた作業を実際に進め、必要ならツールで環境を変え、ユーザー向けの回答を出す段階である。計画だけではファイルも検索も進まないので、副作用と最終回答はこの層に閉じる。記憶バックエンドの直叩きや、計画のやり直しをここに混ぜない。

計画にサブタスクがあるときに使う。知識だけで足りると判断されて実行スキップされたターンでは動かない。サブタスクを順に取り、契約タスクなら決まった手順、そうでなければ LLM がツールを選ぶ。主な経路は ReAct ループとステップドライバの二つ。

## 1. 実行層の位置づけ

```mermaid
flowchart LR
    PLAN["計画層<br/>PlanArtifact"] --> EXEC["実行層"]
    EXEC --> R1["サブタスク 1"]
    R1 --> R2["サブタスク 2"]
    R2 --> RN["サブタスク N"]
    RN --> OUT["TurnResult"]
```

まず計画から作業一覧を受け取る。実行層はその順番を保ち、前の作業の結果を次の作業に引き継ぎながら一件ずつ進める。

すべてが終わったら、各作業の結果を一つのターン結果にまとめる。この基本経路では、後続の作業が前の作業と競合しないよう、同時ではなく順番に扱う。

| 項目 | 計画層 | 実行層 |
|------|--------|--------|
| 頭脳 | `PlanBrainMode` | exec `BrainMode`（`exec_brain`） |
| ループ | `run_plan_layer` | `run_turn_single` → `run_layer_loop` |
| ツール | **不可** | **可**（`ToolRuntime`） |
| 出力 | `PlanArtifact` | 各サブタスクの `Answer` → ターン最終応答 |
| 副作用 | なし | **あり**（`Action` のみ） |

計画層は手順を決めるだけで、環境には変更を加えない。実行層に移った後だけ、必要な操作を一回ずつ行える。

各操作から得た答えはサブタスクの結果として残り、最後にターン全体の返答へまとまる。この分離により、副作用の追跡対象を実行層に限定できる。

**原則**: ファイル操作・シェル・Web 検索など、外部世界への変更は実行層の `Action` だけが行う。

## 2. いつ実行層が動くか

計画層の結果 `PlanArtifact::needs_execution()` が `true` のときだけ実行層に入る。

```rust
// skip_execution == false かつ subtasks が空でない
pub fn needs_execution(&self) -> bool {
    !self.skip_execution && !self.subtasks.is_empty()
}
```

| 条件 | 挙動 |
|------|------|
| `skip_execution: true` | 実行層を省略。元入力に対して単一 ReAct で直接応答 |
| `subtasks` が空 | 同上 |
| サブタスクあり | 各サブタスクを **直列** に実行 |

エントリは `ReActLoop::run_turn_two_phase` または `run_turn_advance`（`advance.enabled: true` 時）。いずれも計画層のあと、同じ `run_subtask_exec_audited` 経由でサブタスクを回す。

## 3. サブタスク 1 件の実行フロー

```mermaid
flowchart TD
    ST["サブタスク開始<br/>prepare_harness_for_subtask"] --> AUD["run_subtask_exec_audited"]
    AUD --> SD{"use_step_driver<br/>かつ steps[] 契約?"}
    SD -->|はい| DRV["run_subtask_driver<br/>LLM なし"]
    SD -->|いいえ| REACT["run_turn_single<br/>ReAct ループ"]
    DRV -->|失敗| REACT
    DRV -->|成功| CHK["audit_subtask"]
    REACT --> CHK
    CHK -->|未達| RETRY["監査メッセージ付き mission で ReAct 再試行<br/>最大 2 回"]
    RETRY --> CHK
    CHK -->|達成| NEXT["PlanProgress に結果を積み<br/>次サブタスクへ"]
```

サブタスクを始める前に、エンジンは現在の作業に必要な文脈と許可されたツールを整える。手順が契約として決まっている場合は、まずドライバがその順番で実行する。

契約がない、またはドライバが失敗した場合は、ReAct に切り替えて必要な手を選ぶ。どちらの経路でも終わった後に契約との照合を行い、不足があれば理由を添えて再試行する。達成できた結果だけを次のサブタスクへ引き継ぐ。

### 3.1 Harness 状態の更新

各サブタスクの直前に `prepare_harness_for_subtask` が呼ばれる。

- `HarnessState.current_step` をサブタスク id に設定
- タスクの `tool_policy` から `tool_set` を注入
- `PromptBlocks.current_step_text` に現在ステップの説明を載せる

実行層の LLM プロンプトには、作業指示書（Harness）と現在ステップの文脈が含まれる。

### 3.2 mission の組み立て

ReAct 経路では `format_mission` がサブタスク専用プロンプトを生成する。

```
## Subtask
id / task / params / goal / done_when

## Task contract
（登録タスクの契約・必須ツール順）

## Prior subtask results
（先行サブタスクの要約 — PlanProgress）

Complete ONLY this subtask. Do not replan or work ahead to other subtasks.
```

先行サブタスクの結果は `PlanProgress` に蓄積され、次サブタスクの mission に引き継がれる（各要約最大 500 文字）。

## 4. 二つの実行経路

### 4.1 ReAct ループ（自由実行）

`run_turn_single` → `run_layer_loop`（`LayerLoopOptions::exec`）

```mermaid
sequenceDiagram
    participant M as mission
    participant B as exec BrainMode
    participant T as ToolRuntime
    participant TR as TurnTrace

    loop max_steps（既定 16）
        M->>B: TurnPromptContext
        B-->>TR: Thought / Action / Answer
        alt Action
            TR->>T: execute_action
            T-->>TR: Observation
        end
        alt Answer
            B-->>M: サブタスク完了
        end
    end
```

ReAct 経路では、まず実行用の頭脳が次の一手を決める。考えるだけなら記録して続け、ツールを選んだときだけランタイムが操作を実行する。

操作の結果は Observation として記録され、次の判断の材料になる。十分な結果が集まって Answer が返れば、そのサブタスクは完了する。上限に達した場合は、それ以上の判断を続けない。

| 設定 | 値（exec） |
|------|------------|
| `tools_enabled` | `true` |
| `context_label` | `"step"` |
| `max_thoughts` | 1（2 回目以降は `__thought_limit` で拒否） |
| `max_steps` | `react.max_steps`（既定 16） |

1 ステップの流れ:

1. `AgentBrain::decide` — `Thought` / `Action` / `Answer` のいずれか
2. `Action` → `execute_action(tools, &action)` → `Observation`
3. trace に蓄積し、次ステップのプロンプトに Observation を含める
4. `Answer` で当該サブタスク（または skip 時のターン）終了

**最少行動単位**は 1 回の `Action`（ツール呼び出し）。`Thought` と `Answer` は副作用なし。

### 4.2 ステップドライバ（契約実行）

`react.use_step_driver: true`（既定）かつ、サブタスクが `tasks/*.json` の登録タスク id を持ち、`steps[]` 契約がある場合。

```mermaid
flowchart LR
    DEF["tasks/list_dir.json<br/>steps[]"] --> DRV["run_subtask_driver"]
    DRV --> S1["step 1: list_dir"]
    S1 --> S2["step 2: …"]
    S2 --> AUD["audit_trace"]
    AUD --> ANS["StepDriverResult.answer"]
```

登録タスクに手順がある場合は、最初にその契約を読む。続いて LLM に選ばせず、記載された順番でツールを呼ぶ。

各操作の記録を最後に監査し、契約どおりの結果をサブタスクの答えとして返す。途中で失敗すれば、この固定経路は成功扱いにせず、呼び出し元が ReAct へのフォールバックを選べる。

- LLM を呼ばず、`steps[]` の `order` 順に `execute_action` を実行
- 引数は `params` をテンプレート展開（`{path}` など）
- 失敗時は **ReAct にフォールバック**
- `generic`（`steps: []`）は契約なし → 常に ReAct

例（`list_dir.json`）:

```json
{
  "id": "list_dir",
  "steps": [
    { "order": 1, "method": "list_dir", "args": { "path": "{path}" }, "required": true }
  ]
}
```

## 5. ツールポリシー

ReAct 経路では、サブタスクに紐づくタスク定義の `tool_policy` により **利用可能ツールを絞り込む**。選定の全体像（ステップドライバ / catalog / mission / 実行時検証）は [02-01_ツールの選択.md](02-01_ツールの選択.md) を参照。

```text
run_subtask_exec
  → tool_policy_for_subtask(subtask)
  → blocks.tool_catalog をフィルタ
  → tools.set_exec_policy(...)
  → run_turn_single
  → ポリシー解除
```

契約外ツールの呼び出しは監査（`audit_trace`）で `complete: false` になる。

## 6. 監査と再試行

`run_subtask_exec_audited` はサブタスク完了後、`TaskRegistry::audit_subtask` で trace を契約と照合する。

| 照合内容 | 状態 |
|----------|------|
| 必須ツールの **呼び出し順序** | 実装済み |
| 禁止ツールの使用 | 実装済み |
| 引数（期待 ⊆ 実引数） | `react.arg_audit_mode`: `soft`（既定）/ `hard` / `off` |

未達の場合、監査メッセージを mission に付加して ReAct で再実行（`SUBTASK_AUDIT_MAX_ATTEMPTS = 2`）。再試行は **ReAct のみ**（ステップドライバは使わない）。`soft` の引数警告だけでは再試行しない。詳細: [task-registry.md](05_タスクレジストリ.md)。

## 7. 1 ターン全体の trace マージ

```mermaid
flowchart TB
    PT["plan_trace<br/>計画層"] --> MERGE["append_trace"]
    E1T["subtask 1 trace"] --> MERGE
    E2T["subtask 2 trace"] --> MERGE
    MERGE --> FINAL["TurnResult.trace<br/>Thought / Action / Observation 一式"]
```

計画中の判断と、各サブタスクで行った操作は、最初は別々の記録として残る。ターンを終える段階で、それらを実行順に一つへつなぐ。

このため最終結果を見ると、計画から各操作とその観測までを一続きで追える。サブタスクごとの結果は別フィールドにも残るので、全体の経緯と個別の成否の両方を確認できる。

ターン終了時、`TurnResult` には以下が含まれる。

| フィールド | 内容 |
|------------|------|
| `answer` | 最後のサブタスク（または skip 時の単一 ReAct）の応答 |
| `trace` | 計画層 + 全サブタスクの trace をマージ |
| `subtask_results` | 各サブタスクの id / answer / steps_used / used_step_driver |
| `steps_used` | 計画 + 実行の合計ステップ数 |

## 8. 設定項目

| キー | 既定 | 実行層への影響 |
|------|------|----------------|
| `react.max_steps` | `16` | 1 サブタスクあたりの ReAct 上限 |
| `react.use_step_driver` | `true` | 契約タスクを LLM なしで実行するか（`react_only: false` 時） |
| `react.arg_audit_mode` | `soft` | 引数監査: `off` / `soft` / `hard` |
| `react.show_task_execution` | `true` | サブタスク開始・完了を stdout 表示 |
| `react.show_tool_output` | `true` | ツール入出力を stderr 表示 |
| `react.two_phase` | `false` | 計画→実行の直列（オン時） |
| `react.advance.enabled` | `false` | フェーズ逐次実行 + `recalled` 引き継ぎ（[advance-loop.md](07_推進ループ.md)） |

## 10. まとめ

- 実行層は **PlanArtifact のサブタスクを直列実行**し、環境への副作用を担う。
- 各サブタスクは **ステップドライバ**（契約あり・LLM なし）か **ReAct ループ**（自由実行）のどちらかで処理される。
- ReAct ループは計画層と同じ `run_layer_loop` だが、`tools_enabled: true` で `exec_brain` + `ToolRuntime` を使う。
- `format_mission` と `HarnessState` により、サブタスク単位の文脈・ツール制限・先行結果がプロンプトに注入される。
- 契約未達時は監査付き ReAct 再試行があり、ターン全体の trace は計画層と実行層をマージして残る。
