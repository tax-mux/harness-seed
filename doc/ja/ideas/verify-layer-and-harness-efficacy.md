# 検証層・差し戻し・ハーネス効き検証（未実装・検討メモ）

ローカル LLM 前提の議論（2026-08-25）から。実装はまだ。コード変更の指示が出るまでメモのみ。

関連: [07_推進ループ](../architecture/07_推進ループ.md)（証拠ゲート）、[00_構造](../architecture/00_harness-seedの構造.md)（計画／実行二層）、[01_計画層](../architecture/01_計画層.md) / [02_実行層](../architecture/02_実行層.md)。単層パスは `two_phase: false` → `run_turn_single`（ライブラリ default）。CLI／sample は二層寄り。

**優先度**: 設計検討。本体の二層＋advance が先。

---

## 1. ローカル前提なら二層本線でよい

| 理由 | 内容 |
|------|------|
| 窓が狭い | 計画中はツールなしで観測ログが膨らまない |
| モデルが弱い | 計画と実行を同時にやると崩れやすい |
| 失敗分離 | 方針ミスは計画側、実装不足は実行側に閉じられる |

例外: 超短問（説明だけ・1ツール）は単層／実行スキップで足りる。

CLI／sample の顔は `two_phase: true`（キー省略時も ON）。ライブラリ `ReActConfig::default()` は単層。**二層本線＋単層パス残し**が現状。

---

## 2. 検証層（第三層）案

```
計画（触れない）→ 実行（触る）→ 検証（確認／差し戻し）
```

検証層の仕事は「再実装」ではなく **判定**:

- テスト／ビルド／grep など決定的チェック
- 「完了」と実装の食い違い（偽完了）
- （ホスト例）Tauri ACL 未登録の機械チェック

| 入れる | 入れない |
|--------|----------|
| 決定的チェック、失敗時は差し戻し（回数上限） | 長い ReAct レビュー |
| 短い固定プロンプト＋ツール少数 | 実行と同じツール全開放 |
| LLM なしスクリプト検証も可 | 検証層での本実装 |

LLM なし検証だけならコンテキストも増えず、ローカル向き。

---

## 3. 差し戻し先

無条件で計画に戻さない。

```
検証失敗
  ├─ 「実装不足」→ 実行へ（回数上限あり）
  └─ 「方針ミス」or 実行上限到達 → 計画へ
```

計画へ戻すとまたツールなしの細い窓で立て直せる。毎失敗で再計画すると二層のトークン利点が消える。

---

## 4. 単層＋Hook いっぱい、について

単層 ReAct ＋ **少数の硬い Hook**（同一ツール連打、noop edit、完了連打、危険操作）は実用的（OpenCode 型）。

Hook を業務ロジックまで増やすと見えない多層になり、単層の素直さが消える。業務の計画・証拠・チケットは **明示フェーズかホスト** 側。

---

## 5. ハーネスの効き具合を検証する

モデル精度と分けて、**ハーネスが効いているか**を測る。

| 指標 | 意味 |
|------|------|
| 拒否率 | identical / 観測連打 / 完了連打を止めた回数 |
| 偽完了捕捉 | 「完了」を検証で落とした回数 |
| 差し戻し | 実行↔検証、計画へ戻った回数と成功率 |
| 暴走長 | 同一 fingerprint の最大連打 |
| 無駄トークン | 計画／実行／検証それぞれの消費 |

やり方:

1. **合成シナリオ** — 悪い動作を意図的に再現し、規定どおり block するか（単体テスト）
2. **固定タスク回帰** — ハーネス ON/OFF・設定差で比較
3. **セッション監査** — 実ログから止めた／通した／差し戻しを集計
4. **検証層との分担** — ハーネス＝手順のストッパー、検証層＝成果物の真偽。両方パスで「効いた」

厳しすぎると正当な再試行まで落ち、成功率だけ見ると悪化して見える。**DoD 達成率＋平均ステップ＋拒否指標**のセットで見る。

最初の安価な一歩: 合成シナリオの自動テストをチェックリスト化（Hermes `opencode-parity-gates` 型と同系統）。
